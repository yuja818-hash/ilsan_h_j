기능 이름보다 작업 흐름을 먼저 확인하세요.

ChatGPT Work가 보일 때교시별 작업을 새 Work로 분리합니다. 독립 검수는 반드시 별도의 새 Work에서 실행합니다.
Work가 보이지 않을 때일반 새 대화에서도 같은 프롬프트를 사용할 수 있습니다. 역할을 순서대로 실행합니다.
파일 생성이 안 될 때코드블록·표로 결과를 받은 뒤 교사가 작업본에 복사합니다. 만들지 못한 파일을 만들었다고 보고하게 두지 않습니다.

공모사업 지원 에이전트팀

PRD 하나로 총괄·분석·작성·독립검수 역할을 만들고, 실제 작성 전 작업계획에서 멈춥니다.

기본 자료PRD starter 또는 승인본, 장영실 PDF, AI역량강화사업 HWP/HWPX 복제본
필수 결과PRD.md, 역할 4개, 준비 작업계획, 독립 검수 오류표
승인선자료 범위 → PRD → 역할 → 작업계획 → 초안 → 보완 → 외부 제출

생기부 작성 지원 Skill

가상 관찰기록을 근거로 Skill을 만들고, 정상 입력과 자료 부족 입력을 시험합니다.

기본 자료Skill starter, 가상 관찰기록, 성취기준 예시
일괄 시연student-record-writer Skill, 30명 더미관찰기록 작업본.xlsx
안전선실제 개인정보 금지, 관찰 근거 부족 시 초안 생성 중단, 교사 승인 전 최종본 금지
3

사업계획서 HWPX 초안

완성형 Skill과 학교 사실카드로 사업 필요성·목표 두 항목만 안전하게 작성합니다.

기본 자료vocational-business-plan-writer.zip, 학교 사실카드, HWPX 작업본
필수 결과사업 필요성·사업 목표 초안, 근거 표시, 사업계획서_초안.hwpx 또는 대응표
원본 보호원본은 보관하고 `_작업본.hwpx`만 첨부·수정합니다.

공개용 HTML과 GitHub Pages

사업계획서 원문이 아니라 승인된 공개 요약만 게시합니다.

가장 쉬운 GitHub Pages 배포

  1. GitHub에서 공개해도 되는 새 저장소를 만들고 index.html을 업로드합니다.
  2. Settings → Pages로 이동합니다.
  3. Build and deployment → Source에서 Deploy from a branch를 선택합니다.
  4. 브랜치는 main, 폴더는 /(root)를 선택하고 저장합니다.
  5. 표시된 공개 주소를 열어 모바일 화면과 링크를 확인합니다.

주의: GitHub Pages 사이트는 인터넷에 공개될 수 있습니다. 민감정보가 없는지 먼저 확인하세요. GitHub 공식 문서에서 최신 절차 확인
